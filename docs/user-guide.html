Database Schema — 10 Models

ModelDeskripsiRelasi Utama
UserPengguna sistem→ WorkspaceMember, CardAssignee, Activity
WorkspaceRuang kerja (multi-tenant)→ Board, WorkspaceMember, Activity
WorkspaceMemberJoin user ↔ workspace + roleRole: ADMIN / MEMBER / VIEWER
BoardPapan Kanban→ Column, Label
ColumnKolom (Backlog, To Do, dll)→ Card, position: Float
CardKartu tugas→ CardAssignee, CardLabel, position: Float
CardAssigneeJoin card ↔ userUnique [cardId, userId]
LabelTag warna per boardUnique [name, boardId]
CardLabelJoin card ↔ labelComposite PK [cardId, labelId]
ActivityAudit trailaction, entityType, metadata (JSON)

RBAC (Role-Based Access Control)

RoleLevelHak Akses
VIEWER0Read-only — lihat board, kartu, activity
MEMBER1CRUD kartu, pindah kartu, assign member, toggle label
ADMIN2Semua hak MEMBER + kelola board, kolom, member
⚠️ Penting Setiap Server Action memvalidasi peran via assertWorkspaceRole() sebelum mutasi database. VIEWER tidak bisa membuat/edit/hapus apapun.

3.4 Manajemen Kartu

Membuat Kartu

  1. Klik "+ Add card" di bawah kolom mana saja
  2. Ketik judul kartu
  3. Tekan Enter atau klik tombol centang

Mengedit Kartu (Modal Detail)

Klik kartu untuk membuka modal. Di dalamnya:

FieldCara Edit

DescriptionKetik di textarea, auto-save saat blur
PriorityPilih dropdown: None / Low / Medium / High
Due DatePilih tanggal dari date picker; "Clear" untuk hapus
LabelsKlik "Labels" → toggle on/off, atau buat label baru
AssigneesKlik "Assignees" → toggle member on/off

Drag & Drop Kartu

  • Pindah dalam kolom: Drag dari ikon ⋮⋮ (kanan atas kartu) ke posisi baru
  • Pindah ke kolom lain: Drag kartu ke kolom berbeda
  • Fractional Indexing: Posisi dihitung otomatis tanpa mengupdate semua kartu di database
💡 Optimistic UI Drag & Drop langsung terlihat instan tanpa menunggu respons server. Jika server gagal, posisi otomatis rollback dan notifikasi error muncul.

# Restore
Copy-Item "prisma/dev.db.backup" "prisma/dev.db" -Force

4.4 Audit Trail

Semua mutasi tercatat di tabel activities:

FieldContoh Isi
actionCARD_CREATED, CARD_UPDATED, CARD_MOVED, CARD_DELETED, CARD_ASSIGNED
entity_typeCARD, COLUMN, BOARD, MEMBER
metadataJSON detail: {"title":"...", "columnId":"..."}
user_idSiapa yang melakukan aksi
created_atTimestamp aksi
-- Lihat aktivitas hari ini
SELECT a.action, u.name, a.metadata, a.created_at
FROM activities a JOIN users u ON a.user_id = u.id
WHERE a.created_at >= date('now') ORDER BY a.created_at DESC;

-- Kartu yang baru dihapus
SELECT * FROM activities WHERE action = 'CARD_DELETED'
ORDER BY created_at DESC LIMIT 10;

5.3 Template Server Action Baru

'use server';
import { prisma } from '@/lib/prisma';
import { getCurrentUser } from '@/lib/auth';
import { assertWorkspaceRole, assertBoardInWorkspace } from '@/lib/rbac';
import { mySchema } from '@/lib/validations/my-validation';

type ActionResult<T = void> =
  | { success: true; data: T }
  | { success: false; error: string };

export async function myAction(input) {
  const parsed = mySchema.safeParse(input);
  if (!parsed.success) {
    return { success: false, error: 'Validation failed...' };
  }

  try {
    const user = await getCurrentUser();
    await assertWorkspaceRole(user.id, parsed.data.workspaceId, 'MEMBER');

    const result = await prisma.$transaction(async (tx) => {
      // mutasi database...
      await tx.activity.create({ data: {
        action: 'MY_ACTION', userId: user.id,
        workspaceId: parsed.data.workspaceId,
        entityType: 'CARD', entityId: '...',
        metadata: JSON.stringify({ /* detail */ }),
      }});
      return { id: '...' };
    });

    return { success: true, data: result };
  } catch (error) {
    return { success: false, error: error.message };
  }
}

5.4 Alur Data — Drag & Drop

1. User drag kartu dari ikon ⋮⋮
2. handleDragEnd() di use-kanban-board.ts
3. Simpan snapshot state saat ini (useRef) untuk rollback
4. Update state secara optimistic (UI langsung berubah)
5. Panggil Server Action: reorderCard() atau moveCardToColumn()
6. Server: Zod validate → RBAC check → calculatePosition() → Prisma update
7a. ✅ Sukses: state tetap
7b. ❌ Gagal: rollback ke snapshot + toast error
